Repository Adobe-Stock-X-Remotion ko Antigravity IDE mein kholo, aur neeche diye gaye 7 prompts ek ek karke sahi order mein paste karte jao — setup se lekar 100 videos ki batch rendering aur final Adobe Stock report tak sab kuch inhi 7 steps mein ho jayega. Duration → Frames ka hisaab

Formula simple hai: frames = seconds × 60. Sirf ye teen durations use hoti hain. 300 frames (5 second) se kam wali video Adobe reject kar deta hai — 240 frames wali 4-second video to pakki reject hai.

Saari motion sin/cos se chalti hai, is liye jahan se video shuru hoti hai, wahin par khatam hoti hai — loop mein koi jhatka (jump) nahi aata.

3 Critical Lessons — jo sab se zyada kaam aayengi

LESSON 1

Duration ka hisaab galat = video reject

Frames = seconds × fps. 8s = 480, 10s = 600, 12s = 720 frames, aur kam se kam 300 frames (5 second) lazmi hain. Agar kisi prompt ki duration galat ya bohat chhoti ho, to use valid duration (default 10s / 600) par fix karke report mein bataya jata hai.

LESSON 2

Bitrate: 40M, CRF kabhi nahi

Hamesha --video-bitrate=40M use hota hai, target taqreeban 30–40 Mbps. --crf dark ya simple scenes par sirf ~2 Mbps de deta hai aur Adobe "quality too low" ka flag laga deta hai. CRF aur bitrate ko kabhi combine na karein.

LESSON 3

Black wallpaper kabhi nahi bikti

Pure ya near-black background wali video ka thumbnail hi nahi banta. Is liye base hamesha palette ke hue mein thoda sa lifted dark (taqreeban 12–15% lightness) hota hai, plus usi rang ki halki radial BackgroundGlow — frame mein hamesha ek wazeh roshni wala hissa aur kaafi bright elements nazar aayein.

Remotion ke ghair-mutabadil rules

  • Seamless loop: saari motion useCurrentFrame() se sin/cos par — frame 0 aur aakhri frame bilkul barabar. Multiple cycles ke liye 2π ke integer multiples; particles modulo se seamlessly wrap hote hain.
  • Math.random() kabhi nahi: Remotion ka seeded random("seed") use hota hai, har prompt ka apna unique seed. Deterministic matlab koi flicker nahi.
  • Sab @remotion/* packages ki version bilkul ek jaisi honi chahiye.
  • Backgrounds ke liye fonts / loadFont() blocking avoid karein.
  • Grain sirf halka sa; video clean, in-focus — na over-sharpened, na over-contrasted.
  • Koi logo, brand, trademarked font, copyrighted material ya text nahi.
  • Is machine class par NVENC nahi hai — encoding CPU (libx264) par hoti hai, aur ye bilkul theek hai.

Ek achhe prompt ke andar kya hota hai?

Prompt mein sirf creative spec hoti hai: naam, composition ID, resolution / fps / duration + frames, seamless loop ki statement, type, motion, seeded random, exact hex colors + lifted base + radial glow, effects, mood, aur files ki list. Render flags prompt ke andar kabhi nahi hote — woh hamesha remotion.config.ts mein rehte hain (OpenGL 'angle', concurrency 8, codec h264, bitrate 40M, yuv420p, bt709, muted).

Save karne se pehle self-check: frames = seconds × 60 aur ≥ 300 · loop statement sahi · seed unique · hex colors exact · lifted base + glow maujood · bright elements kaafi · Files line mein BackgroundGlow.tsx shamil · koi render flag, logo ya text nahi.

boost_bitrate.py — ek optional tool (hoshiyari se)

Doc mein ek Python script hai jo kisi folder ki saari MP4s ko high bitrate (default 45M, 40M–50M theek hai) par re-encode karke adobe_ready subfolder mein daal deti hai — originals mehfooz rehte hain aur 25 MB se bari files skip ho jati hain. Ye Adobe ke "quality too low" flag ka ilaaj hai, lekin Prompt 7 ki hidayat wazeh hai: pehle zaroorat inspect karein aur authorization lein — sirf file size barhane ke liye re-encode mat karein, aur bina poochhe saari outputs par mat chalayein.

Remotion perfect banata hai

Sab code aur math hai — koi external asset nahi, perfect loops, crisp 4K.

  • Gradient animations — mesh, aurora, color transitions
  • Geometric / shapes — floating shapes, rotating patterns, kaleidoscope, grids, low-poly
  • Particles — dust, bokeh, bubbles, snow, confetti, starfield, fireflies, plexus connected dots (corporate favorite)
  • Waves / lines — sine waves, waveform bars, ribbon / silk, contour lines
  • Abstract / tech — digital rain, hexagon grids, circuits, glitch / scanline, neon
  • Loops / patterns — seamless tiles, infinite scroll, spirals

Shuru mein in se bachein

Ye cheezein Remotion ke bas ki nahi — inke liye stock footage ya AI video behtar hai.

  • Realistic smoke / fire / water — fluid simulation chahiye, bohat heavy
  • Realistic 3D scenes — Three.js slow render karta hai
  • Real-footage looks — badal, samandar waghera asal video hain, code nahi
  • Complex physics — kapra (cloth) ya liquid simulation engine maangta hai

Aam errors aur unka hal — Troubleshooting

Kaam ke dauran ye maslay sab se zyada aate hain. Agar aapko in mein se koi error nazar aaye, to ghabrayein nahi — pehle yahan uska hal parhein, phir wahi step dobara check karein jis ki taraf har jawab ishara karta hai.

?Video bilkul black aaye, ya thumbnail hi na bane

Sab se pehle ye teen cheezein check karein: (1) render mein --gl=angle use hua hai ya nahi — iske baghair heavy blur wali scenes black render ho jati hain. (2) Background pure black to nahi — base hamesha lifted dark (taqreeban 12–15% lightness) hona chahiye, usi rang ki radial glow ke saath. (3) Final render se pehle still preview zaroor dekhein — preview black ho to pehle wahi fix karein, poori video render karne mein waqt zaya na karein.

Ye check kahan hai: Prompt 1 (configuration + sample) · Prompt 5 (still preview)
?Adobe kahe: "video quality may be too low"

Iska matlab aksar ye hota hai ke bitrate bohat kam reh gaya. Wajah taqreeban hamesha CRF hoti hai — dark scenes par CRF sirf ~2 Mbps de deta hai. Hal simple hai: CRF bilkul use na karein, hamesha --video-bitrate=40M rakhein, aur ffprobe se verify karein ke asal bitrate taqreeban 30–40 Mbps hai. Agar phir bhi koi purani file low-bitrate nikal aaye, to boost_bitrate.py ka option mojood hai — lekin sirf tab, jab waqai zaroorat ho aur aapne ijazat di ho; sirf file size barhane ke liye re-encode na karein.

Ye check kahan hai: Prompt 1 (render settings) · Prompt 7 (bitrate verification)
?Video sirf 4 second ki ban jaye, ya Adobe reject kar de

Ye duration ka hisaab galat honay ki nishani hai. Formula yaad rakhein: frames = seconds × 60. Sirf ye teen durations sahi hain — 8s = 480, 10s = 600, 12s = 720 frames — aur kam se kam 300 frames (5 second) lazmi hain. 240 frames wali 4-second video pakki reject hai. Agar kisi prompt mein frames kam likhe hon, to use valid duration (default 10s / 600 frames) par fix karein.

Ye check kahan hai: Prompt 3 (frame counts) · Prompt 4 (validation)
?Loop ke aakhir mein jump / jhatka nazar aaye

Seamless loop ka matlab hai: frame 0 aur aakhri frame bilkul ek jaise hon. Ye tabhi hota hai jab saari motion sin/cos par chale — periodic motion khud ba khud apni shuru wali position par wapas aa jati hai. Agar kahin linear (seedhi) motion use ho gayi ho, to element aakhir mein apni jagah se aage nikal jata hai aur loop wapas shuru hote hi jump marta hai. Us hisse ki motion sin/cos mein badlein aur dobara preview dekhein.

Ye check kahan hai: Prompt 2 (production rules) · Prompt 7 (loop-boundary check)
?Video flicker kare — elements hilte-jhulte nazar aayein

Flicker ki sab se aam wajah Math.random() hai — ye har frame par naye random numbers banata hai, is liye dots aur particles har frame idhar udhar uchhalte hain. Qaaida wazeh hai: Math.random() bilkul nahi. Uski jagah Remotion ka seeded random("seed") use karein — ek hi seed har frame par ek hi result deta hai, aur har prompt ka apna unique seed hota hai. Code mein Math.random() jahan bhi mile, use seeded random se badal dein.

Ye check kahan hai: Prompt 2 (prompt writer rules) · Prompt 4 (seed checking)
?Ek prompt se kai videos ban jayein

Ye parser ka masla hai: generator Prompts/Prompts.txt ki har line ko ek job samajhta hai. Agar ek mukammal prompt ghalti se kai lines mein toot gaya, to wo kai alag videos ban jayega. Qaaida yaad rakhein: ek complete prompt = ek hi job — ya to har prompt bilkul ek physical line par ho, ya block-aware parser pehle test ho chuka ho. Agar ye masla ho jaye, to batch rok kar pehle file theek karein aur validation dobara chalayein.

Ye check kahan hai: Prompt 2 (parser compatibility) · Prompt 4 (final validation)
?Local AI / model na mile, agent paid API ki taraf jaye

Agar local model available na ho, to ruk jayein — agent ko khud se koi paid API use nahi karni, na hi chup chaap provider badalna hai. Sahi tareeqa ye hai ke agent masla saaf taur par report kare ke kya missing hai. Agar test ke liye procedural template use ho, to use hamesha waisa hi label karein — procedural cheez ko LLM-generated kabhi na kahen. Bara model download karne se pehle bhi aapki ijazat lazmi hai.

Ye check kahan hai: Prompt 1 (Local AI section) · Prompt 5 (model na mile to stop & report)
